# FTC Scout V2 — исправленная версия (2026-10-24)

**Статус:** код и локальные тесты подготовлены. Прямого подключения к рабочему Google Sheets и развёртывания Apps Script у автора пакета не было, поэтому реальную доставку нужно проверить по инструкции ниже. Это **не** подтверждение, что работающий сайт уже обновлён.

## Архитектура

- **GitHub Pages**: `index.html`, `app.js`, `api.js`, `queue.js`, `storage.js`, `config.js`, CSS, Service Worker, иконки и манифест. Всё редактируемо через GitHub.
- **Google Apps Script**: исходники в каталоге `apps-script/` в том же GitHub-репозитории, но эти исходники нужно развернуть как реальное приложение Apps Script: GitHub Pages не может сам писать в закрытую Google Таблицу.
- **Google Таблица**: листы `Team`, `MatchLocks`, `RawData`, `Qualifications`, `Average`; `Logs` можно оставить. Существующие строки не удаляются при запуске `setupProject`.
- **Admin**: только внутри Google Таблицы через меню `FTC Scout`, не через общедоступную страницу. Не хранить админ-пароли в браузере и репозитории.

## Что исправлено

1. Бывший `fetch()` из GitHub Pages в `script.google.com` не работал стабильно из-за CORS/redirect. Публичная сторона использует проверяемый JSONP (`apiVersion:2`), а Apps Script имеет только разрешённые действия (ping, getTeams, getMatches, getRanking, getStats, submit).
2. Сохраняем запись в IndexedDB (резервный режим localStorage) **до** сетевого запроса; клиент удаляет её только после ответа `{success:true,stored:true,submissionId:...}`.
3. На сервере `submissionId` — защита от дублей при повторной отправке, `LockService` защищает одновременную запись.
4. Запись поступает в `RawData`. Если `REQUIRE_APPROVAL=false`, она сразу обновляет `Qualifications` и `Average`; если `true` — видна в `RawData` и ожидает подтверждения админа.
5. Исправлены несовпадавшие заголовки листа RawData: `Win` (12), `User` (13), `Approved` (14), новый `SubmissionId` (15). Данные остаются на прежних позициях.
6. Пересчёт `Qualifications` выполняется пакетно. В строке `Total RP` записывается сумма очков, а не текст с перечислением.
7. Кнопка удаления данных строго административная, очищает ID, но не уничтожает список матчей. Старый публичный пароль удалён.
8. Старые записи `localStorage.queue` мигрируют в новую очередь с устойчивыми ID при первом запуске нового приложения. После успешной миграции старая очередь удаляется.
9. Service Worker сохраняет основную оболочку приложения для запуска без интернета. Для графиков и CSV не нужны внешние CDN.

## Развернуть Apps Script — обязательно

1. **Сделайте копию текущей Google Таблицы.** Лист в `.xlsx`, который прилагался, — только снимок, а не активное соединение с Google.
2. Откройте **действующую Google Таблицу** → **Расширения → Apps Script**. Это важно: для меню администратора проект должен быть привязан к таблице.
3. В редакторе замените/создайте файлы **`Code.gs`**, **`Api.gs`**, **`Statistics.gs`**, **`Admin.html`** из папки `apps-script/`. Удалите/отключите старые `.gs` файлы с одноимёнными функциями `doGet`, `getSheet`, `getRawDataRows`, `submitScoutData` во избежание дубликатов. `Utils.js` старого архива не требуется.
4. **Настройки проекта → Свойства скрипта** (Script properties):
   - `SPREADSHEET_ID`: ID **реальной Google Таблицы** из её адреса `https://docs.google.com/spreadsheets/d/ВАШ_ID/edit`.
   - `ADMIN_EMAILS`: email администратора Google, допускается несколько через запятую; **не публиковать** это значение в GitHub.
   - `REQUIRE_APPROVAL`: `false` для немедленного отображения полученных данных в `Qualifications` и `Average` или `true` для ручного подтверждения в админ-панели.
5. Вручную запустите функцию **`setupProject`**, разрешите доступ к Google Sheets. Функция обновляет только шапку `RawData` и создаёт недостающие листы. Она не удаляет записи.
6. Вручную запустите **`forceUpdateData`**. Она перестроит `Qualifications` и `Average` **только из одобренных записей**. Если часть старых записей со статусом `FALSE`, их нужно проверить и подтвердить через меню таблицы.
7. **Развернуть → Новое развёртывание → Веб-приложение** (либо отредактировать существующее развёртывание и создать новую версию). Выполнять от вашего имени (`Execute as: Me`), доступ: `Anyone / Все`, если для публичного скаутинга не предполагается авторизация. Скопируйте URL, который **заканчивается на `/exec`**. Не используйте `/dev`.
8. Откройте `<URL_ВЕБ-ПРИЛОЖЕНИЯ>?action=ping` в браузере. Ожидается JSON: `{"success":true,"version":"2026-10-24-2","apiVersion":2,"status":"connected"}`. При ошибке проверьте `SPREADSHEET_ID`, права и разрешения.
9. В **`config.js`** на GitHub подставьте **текущий** `/exec` URL. Старый URL в пакете оставлен для удобства миграции, но без повторного развёртывания нового серверного кода он работать не будет.

## Загрузить клиент на GitHub

1. Скопируйте файлы из **`replace-in-github/`** в **корень** репозитория `Ilia2078/ftc-scout-v2` (в релизном ZIP они уже находятся в корне). Перезапишите `index.html`, `app.js`, `api.js`, `queue.js`, `storage.js`, `style.css`, `service-worker.js`, `manifest.json`, добавьте `config.js` и `icons/`.
2. Добавьте папку **`apps-script/`** в GitHub для хранения исходников сервера. Развёрнутый Apps Script **не синхронизируется автоматически** при коммите GitHub: для этого потребуется `clasp`/CI и аутентификация Google. **Не сохраняйте** `.clasp.json`, токены OAuth или секреты в общедоступном репозитории.
3. Удалите старые неиспользуемые браузерные модули `charts.js`, `export.js`, `offline.js`, `search.js`, `settings.js`, `statistics.js`, `sync.js`, `ui.js` — новый интерфейс полностью работает от `app.js` и четырёх перечисленных модулей. Удалять старые файлы необязательно, но они больше не импортируются.
4. GitHub Settings → Pages: source `Deploy from a branch`, branch `main`, folder `/(root)`. Откройте `https://ilia2078.github.io/ftc-scout-v2/`, обновите страницу после публикации; первый запуск должен быть онлайн.

## Проверка сквозного соединения

1. Откройте сайт, увидите **«Сервер доступен»**. При «Нет связи с таблицей» сначала проверьте `ping` и `config.js`.
2. Отправьте тестовый матч для существующей команды и **разблокированного** матча (проверьте `MatchLocks`). Вкладка «Очередь» должна стать `0`. В рабочей Google Таблице должна появиться новая строка `RawData` с уникальным `SubmissionId` в колонке O.
3. При `REQUIRE_APPROVAL=false` в `Qualifications` и `Average` должны появиться рассчитанные данные; при `true` сначала одобрите отправку через администратора.
4. Выключите Wi-Fi/мобильную связь, отправьте ещё одну запись; «Очередь» должна показать `1`. Перезапустите приложение — запись должна остаться. Включите сеть, откройте PWA, нажмите «Отправить сейчас». В Google Sheets должна появиться одна строка, без дубля при повторном нажатии.
5. На iPhone: **Safari → Поделиться → На экран Домой** после первого полноценного онлайн-запуска; **откройте установленное приложение ещё раз онлайн**, чтобы его отдельное хранилище заполнилось. Затем откройте приложение без сети, проверьте отправку и сохранение после закрытия/открытия. Сервис-воркер не гарантирует, что iOS вечно сохранит данные: делайте резервную копию очереди (кнопка «Скачать копию») перед длительной офлайн-работой и после неё.

## Безопасность и ограничения

- Публичная запись через JSONP (GET) не является приватной и требует доверия к пользователям. URL публичен, случайные посетители могут попытаться отправлять данные. Для соревнования с внешними участниками включайте `REQUIRE_APPROVAL=true`. Для настоящей авторизации скаутов нужен отдельный сервер с login/token и корректными CORS/POST.
- Нельзя хранить пароль админа в `index.html`, его видел каждый посетитель старого сайта. **Смените прежний пароль, если повторно использовали его где-либо.** Сейчас административный доступ опирается на аккаунт Google в контексте привязанной таблицы.
- Не используйте `ContentService` JSONP для выдачи персональных списков, адресов электронной почты или секретов.
- Отсутствие сети, закрытый матч, неверная команда, старое развёртывание и ошибка сервера не стирают локальную очередь. При длительной ошибке откройте вкладку очереди и посмотрите причину, не нажимайте «Удалить запись», если хотите её сохранить.
- iOS Safari может очистить данные сайтов при нехватке памяти/пространства; абсолютно безусловную офлайн-персистентность веб-приложение обеспечить не может.
- Для Web App публичное чтение/отправка и admin-sidebar разделены. Если `Session.getActiveUser().getEmail()` пуст, административные функции намеренно откажут в доступе.

Нужен Node.js 20+. В корне пакета: `npm test`. Тесты проверяют миграцию заголовков, запись RawData, публикацию в Qualifications, запрет публичного Admin, идемпотентность и сохранение очереди при ошибке API. Они **не заменяют** проверку настоящих сервисов Google и Safari.

## Исправление Qualifications и счётчиков (26.10.2026)

- В приложении попадание **+** увеличивает и попадания, и число артефактов; попадание **−** не уменьшает артефакты. Артефакты **−** не могут стать меньше попаданий. Всё работает в офлайн-режиме на iOS/Android.
- Уже существующий лист `Qualifications` в таблице FTC leaderboard biobuzz исправлен по подтверждённым данным `RawData` 26.10.2026. Это разовое восстановление.
- **Чтобы все следующие отправки автоматически обновляли Qualifications**, в Google Apps Script откройте `Code.gs`, найдите в функции `submitScoutData(data)` вызов `writeToQualifications(row);` и замените его на `rebuildQualifications_();`. Альтернатива: добавьте файл [apps-script/RepairQualifications.gs](apps-script/RepairQualifications.gs) в Apps Script и вызовите `ftcRepairQualifications();` вместо `writeToQualifications(row);`. Архив обновлённого проекта также содержит полный серверный `Code.gs` с исправлением.
- Сохраните серверный код, запустите `forceUpdateData` один раз (или `ftcRepairQualifications` с альтернативным файлом), затем обязательно выпустите **новую версию существующего веб-развёртывания** через `Развернуть → Управление развёртываниями → Изменить → Новая версия → Развернуть`. Новый серверный код не применяется автоматически при коммите на GitHub.
- Пока на устройстве есть неотправленные записи, **не очищайте кэш и хранилище сайта**. Обновление Service Worker не удаляет очередь IndexedDB.

## Восстановление Average (2026-10-26)

Если записи присутствуют в `RawData`, но в `Average` отсутствует часть
матчей, скопируйте [`apps-script/RepairAverage.gs`](apps-script/RepairAverage.gs)
в связанный с Google Таблицей редактор Apps Script, задайте свойство
`SPREADSHEET_ID` и вручную запустите `ftcRepairAverage()`.

Функция считает все строки `RawData` с `Approved=TRUE` (колонка N).
Счётчики `Q Count`, проценты попаданий по сумме попыток и средний
`Total RP = (Parking + Pattern + ArtifactsRP + 3*Win) / Q Count`
пересчитываются из исходных записей. Строки `RawData` не изменяются,
вкладка `Average` сохраняет шапку, пустую строку 2 и оформление.
Сортировка существующих команд также не меняется.

Для **автоматического** пересчёта разместите `ftcRepairAverage();`
после записи и одобрения новой строки в `submitScoutData(data)`, а также
после ручного подтверждения в панели администратора. Пересчёт
`Qualifications` и `Average` лучше вызывать в **раздельных**
`try/catch`, чтобы ошибка одного отчёта не блокировала второй:

```javascript
if (approved) {
  try { rebuildQualifications_(); } catch (err) { console.error('Qualifications:', err); }
  try { ftcRepairAverage(); } catch (err) { console.error('Average:', err); }
}
```

Этот фрагмент заменяет прежний блок обновления в случае, если сервер
использует функции `rebuildQualifications_` и `submitScoutData` из
`Code.gs`. Если текущий проект использует
`ftcRepairQualifications()`, оставьте этот вызов вместо
`rebuildQualifications_()`. После изменения Apps Script обязательно
**создайте новую версию существующего Web App deployment**. Один лишь
коммит в GitHub не обновляет исполняемый Apps Script.

При `REQUIRE_APPROVAL=true` записи без подтверждения не участвуют
в `Average`; вызов после подтверждения администратором обязателен.
